多层查看区 Demo

这份 demo 不是最终实现代码，而是把新版工作台里缺失的“跨世界书多条目同时查看”能力拆成独立层级： 当前编辑区、世界书查看层、条目堆栈层、双槽对照层、手机查看标签层。 目标是保留现在的清晰布局，同时追回旧版最核心的跨书对照能力。

主仓库维护 只读查看优先 跨世界书对照 手机单独查看入口
第一层：主编辑区 始终只保留一个当前编辑上下文，避免编辑状态混乱。
第二层：查看堆栈 可加入多个来自不同世界书的条目，只读浏览，不打断当前编辑。
第三层：双槽对照 专门用于“世界书 A 条目 X”和“世界书 B 条目 Y”的同步对照。

实现思路拆解

正式落地时，建议按下面的状态结构实现，而不是回退到旧版双编辑器并排模式。

状态 1：当前编辑

`currentEditor = { worldbook, uid }`

只允许一个主编辑上下文，避免保存时冲突。

状态 2：查看池

`inspectBuckets[worldbook] = InspectItem[]`

按世界书分桶，每桶维护多个只读条目卡。

状态 3：双槽对照

`compareSlots = { left, right }`

专用于对照，不直接改内容。

手机端建议：单独增加“查看”标签

不要把“查看”混进“编辑”或“条目”里，否则还是会误触和抢上下文。

对照层

手机不建议左右并排，可改成上下切换的“双层详情”或“左右滑动槽位”。

为什么手机要单独做“查看”标签

手机最怕的是一个点击同时承担三件事：选中、查看、编辑。这样误触不可避免。最稳妥的结构是：

条目标签
负责选中、搜索、排序、快速打开查看或编辑入口。
查看标签
负责只读堆栈、跨世界书内容巡检、双槽对照。
编辑标签
只负责当前一个条目的集中修改，不再承担查看职责。
